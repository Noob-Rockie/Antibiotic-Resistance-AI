## Project identity

**Explainable Machine Learning for Antibiotic Resistance Prediction and Clinical Decision Support** — an academic research prototype. Predicts laboratory non-susceptibility for an identified isolate, explains the prediction with SHAP, ranks agents for clinician review with cited guardrails, and keeps a human in the loop. It is **not** a prescribing system.

## Dataset relationships

`anon_id` → `pat_enc_csn_id_coded` → `order_proc_id_coded`. **`order_proc_id_coded` is the single join key.** Only `demographics` is 1:1 (100% coverage). `labs` (65.6% of orders), `resistance` (22.2%) and `prior_med` (76.6%) are one-to-many and are aggregated to one row per key BEFORE joining — a raw join would fan out up to 748×. All merges go through `validated_merge()` in `scripts/04_build_analytic_dataset.py`, which raises rather than silently corrupting.

## Target variable

- **Primary:** `y_nonsusceptible` — 1 = Resistant or Intermediate, 0 = Susceptible. **19.52% positive.**
- **Secondary:** `y_3class` — Susceptible / Intermediate / Resistant (45,162 Intermediate rows). Trained and reported, but Intermediate recall is poor — which is the empirical reason the primary task groups it with Resistant.
- `Inconclusive` and `Synergism` (4,602 rows) are removed: they are not single-agent phenotypes.

## Feature-selection methodology

Seven methods → four+ candidate sets → compared on held-out validation patients → highest PR-AUC wins (`C_model_based_XGB_top30`).

**Leakage check:** re-deriving the selection inside every CV fold scores 0.75861 vs 0.75963 for the global list — optimism +0.00102 PR-AUC. Negligible.

## Data preprocessing

- Organism normalisation: strip `ZZZ` prefixes, reconcile `(GROUP B)`/`{GROUP B}`, collapse `… COMPLEX`, extract morphotype, **strip resistance phenotype tokens** (`src/preprocessing/organism_normalizer.py`).
- Duplicate resolution: most-resistant-wins (11,785 conflicting groups).
- Labs collapsed to one row per order by median of non-missing.
- Prior medications: `t == 0` (same-day) excluded; repeated same-drug-same-day collapsed; class derived from drug NAME.
- History features: cumulative sums **shifted** to exclude the current order.
- Trees: ordinal category codes, NaN preserved. Linear models: one-hot + median impute + standardise (separate pipeline).

## Explainability method

SHAP `TreeExplainer` (exact Shapley values). One implementation in `src/explainability/shap_explainer.py`, used by the feature selection stage, the XAI report and the live application — so what selects a feature and what explains it to a clinician are the same computation.

## Recommendation logic

`08_RECOMMENDATION_ENGINE/antibiotic_ranking.py` scores every candidate agent, attaches SHAP factors and guardrail flags from `recommendation_rules.py`, and orders unflagged options by predicted susceptibility with flagged options ranked below — **never removed**. Framing is always "potential options for clinician review".

## API integrations

- **openFDA drug label** — verbatim dosage text. Route-ranked so a systemic label is chosen over an ophthalmic one (this was a real bug: searching "ciprofloxacin" returns eye drops first).
- **RxNorm / RxNav** — name normalisation. No key.
- **CMS NADAC** — unit acquisition cost. No key.
- **NOT used:** RxNav Drug Interaction API — retired by NLM, verified to return "Not found".
- All calls go through `10_API_SERVICES/_http.py`: timeout, disk cache, `ApiResult` envelope with source + retrieval timestamp, never raises, `ENABLE_LIVE_API=0` disables everything.

## Important architectural decisions

1. **One unified model with the antibiotic as a feature** — not 54 per-agent models, not multi-label. Tested empirically in `docs/MODEL_EVALUATION.md` §11.
2. **Prediction moment fixed at post-identification, pre-AST.** This is what makes the organism a legal feature; an organism-blind ablation quantifies the alternative.
3. **Patient-grouped splits + a temporal holdout**, reported side by side.
4. **Guardrails flag, never filter.** Nothing is hidden from the reviewing clinician.
5. **Dosage is relayed, never computed.** Cost is retrieved, never estimated.
6. **Every document in `docs/` is generated from JSON artefacts**, so published numbers cannot drift from the data.
7. **Raw data is referenced in place, never copied or written.** Enforced by tests.

## User acceptance testing

**Result: PASS** - 57/59 tests passed (2 failed, both fixed and re-tested; 0 outstanding). Pass rate 96.6% as first run, 100% after fixes. 0 crashes across 32 invalid-input tests. Regression suite: 111 passed, 0 failed (identical before and after the fixes).

Tested against 60 held-out cultures (1,003 agent-level comparisons). The case menu is deliberately enriched for difficulty and this figure is NOT the model's accuracy, which remains 0.88583 on the held-out test partition.

Performance: startup 32.7s cold; prediction for 54 agents 0.066s; SHAP 3.61s; full ranking 3.67s. SHAP is 98.3% of ranking time - the slow first load is expected, not a defect.

Two defects were found and fixed, both confined to the external-API name-resolution layer - no model was retrained and no measured performance number changed. Correct dosage references rose 39/54 to 47/54, wrong-drug labels 6 to 0, cost coverage 27/54 to 33/54.

- **BUG-01 (high, fixed)** - Wrong drug's FDA label displayed as the dosage reference. FIX-01 - drug identity guard in 10_API_SERVICES/drug_api.py discards any label not naming the requested ingredient; mismatches 6 -> 0.
- **BUG-02 (medium, fixed)** - Combination antibiotics had neither dosage nor cost data. FIX-02 - separator-agnostic lookup plus four verified mappings in 10_API_SERVICES/drug_api.py.
- **BUG-03 (low, deferred)** - Confidence band ignores evidence strength. Deferred - changes clinical presentation on every option card and should be a deliberate design decision.
- **BUG-04 (low, deferred)** - Deprecated Streamlit use_container_width parameter. Deferred - should be a standalone change before any Streamlit upgrade.

Full report: `12_TESTS/USER_ACCEPTANCE_TEST_REPORT.md` - report summary: `14_REPORT_MATERIAL/USER_TESTING_SUMMARY.md` - test table: `14_REPORT_MATERIAL/tables/user_testing_summary.csv`.

## Known problems / open issues

- Prior-resistance history covers only ~38% of orders; absence of a record is not absence of exposure.
- Panel-selection bias is acknowledged but not modelled.
- No external validation cohort exists.
- Streamlit `@st.cache_data` hashes the record dict on every input change; scoring 54 agents with SHAP takes a moment on first load.
- The 3-class model's Intermediate recall is low; this is a property of the AST category, not a fixable defect.
- Confidence band ignores evidence strength (BUG-03, low, open after UAT). The band is computed from distance from 0.50 only, so an agent with zero training examples can read 'confidence: high' beside an evidence band of 'none - extrapolated'.
- Deprecated Streamlit use_container_width parameter (BUG-04, low, open after UAT). Used in 20 places; scheduled for removal but still functional in the pinned version. Warning is never visible to users.
