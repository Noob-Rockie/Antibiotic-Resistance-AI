# Data Leakage Analysis

> Auto-generated by `scripts/05_generate_analysis_docs.py` from `02_DATA_ANALYSIS/reports/leakage.json` and `01_DATA/processed/build_report.json`.

This is the single most important document in the project. In a medical prediction task, a model that reads any part of its own answer will look excellent offline and be useless — or dangerous — in practice.

## 1. The prediction moment

Leakage is only definable relative to a prediction time point, so the project fixes one explicitly:

> **T = the moment the organism identification is available for a positive culture, and before the antimicrobial susceptibility test (AST) result is reported.**

This is a real clinical gap. Organism identification (Gram stain, MALDI-TOF, rapid molecular panels) typically lands roughly 24 hours before the full AST panel. During that window the clinician must choose or continue therapy with the organism known and its susceptibility unknown. Everything the model is allowed to see must exist at T:

* patient demographics and the specimen/order context — known at collection;
* laboratory results from the 14 days before the culture — known;
* prior medications, prior cultures and prior resistance from earlier encounters — known;
* the identified organism — known at T by definition;
* **the susceptibility result itself, or anything derived from it — NOT known.**

## 2. Confirmed leakage found and removed

### 2.1 Resistance phenotype embedded in the organism name

The `organism` column is a laboratory dictionary dump, and some of its entries carry the answer in the text:

| Raw organism value | Rows |
|---|--:|
| tokens matched: `MRSA` | 16,592 |
| tokens matched: `CARBAPENEM_RESISTANT` | 4,861 |
| tokens matched: `VANCOMYCIN_RESISTANT` | 426 |

In total **21,879 rows** (1.386% of the modelling rows) carry a resistance token such as `STAPH AUREUS {MRSA}`, `KLEBSIELLA PNEUMONIAE (CARBAPENEM RESISTANT)` or `ENTEROCOCCUS FAECIUM -  VANCO RESISTANT`.

The tokens are demonstrably the label restated. Comparing the resistant rate for rows carrying a token against the background rate for the same antibiotic class:

| Token / antibiotic class | Rows with token | % Resistant with token | % Resistant, class baseline |
|---|--:|--:|--:|
| `CARBAPENEM_RESISTANT_vs_Carbapenem` | 273 | **37.0%** | 2.75% |
| `MRSA_vs_Cephalosporin` | 427 | **35.36%** | 13.2% |
| `VANCOMYCIN_RESISTANT_vs_Glycopeptide` | 74 | **100.0%** | 2.83% |

**Action taken.** `src/preprocessing/organism_normalizer.py` strips every resistance token into a separate field, that field is dropped before modelling, and the cleaned species name is what the model sees. The morphotype tokens in the same column (`MUCOID`, `NON-MUCOID`, `COLONY VARIANT`) are *not* leakage — they are colony appearance observed at identification — so they are preserved as the feature `organism_morphotype`.

### 2.2 `was_positive`

Cross-tabulating `was_positive` against the target shows it is a deterministic restatement of whether a label exists at all:

| `was_positive` | Rows with a susceptibility result | Rows with no result |
|---|--:|--:|
| `0` | 0 | 630,798 |
| `1` | 1,606,582 | 3,670 |

Every `was_positive = 0` row has no susceptibility result, and every labelled row has `was_positive = 1`. After the modelling cohort is filtered to labelled rows the column is constant (`['1']`) — zero variance and, in principle, culture-result information. **Action taken: excluded.**

### 2.3 Same-day medication administrations

`medication_time_to_culturetime` reaches down to 0 days, and **1,034,527 rows (10.53% of the prior medication file)** sit exactly at 0.

> A medication recorded 0 days from the culture cannot be distinguished from empiric therapy started immediately AFTER the specimen was collected. Including it would leak the treating clinician's response to the very episode being predicted, so all t == 0 rows are excluded.

**Action taken.** All `t == 0` rows are dropped (1,034,527 rows). Only `t >= 1` contributes to the prior-exposure features.

### 2.4 Identifiers

`anon_id`, `pat_enc_csn_id_coded` and `order_proc_id_coded` are arbitrary surrogate keys. They carry no clinical meaning, but they are highly predictive in a leaky way: a tree can memorise a patient key and recall that patient's outcome. **Action taken: all three are excluded from the feature matrix and retained only as split metadata** (`anon_id` groups the split, `order_proc_id_coded` links predictions back to a culture).

### 2.5 Redundant duplicate of the index culture time

`microbiology_cultures_microbial_resistance.order_time_jittered_utc` is byte-identical to the cohort's order time for all 166,537 orders compared. It is the *index* culture time repeated on every history row, not the time of the prior event. **Action taken: excluded as a duplicate column**; the prior event's timing is carried by `resistant_time_to_culturetime` instead.

## 3. Variables investigated and CLEARED

### 3.1 Prior resistance history — cleared, and it is the strongest signal

This table looked like the most dangerous candidate: it contains organism-antibiotic resistance events keyed on the *index* culture order. Three independent checks establish that it is history, not the answer.

1. **Timing.** `resistant_time_to_culturetime` has minimum **1.0** day and **0** rows at or below zero (median 758.0 days, 1st percentile 18.0 days). Every event predates the index culture by at least a day.
2. **Match rate.** Joining it to the cohort on (order, organism, antibiotic) matches only 92,459 of 2,241,050 rows (4.1257%). A leaked label would match nearly everything.
3. **Predictive but not deterministic.** Among matched rows 63.7% are Resistant, versus 13.7% among unmatched rows. That is a large, clinically plausible lift — a patient with documented prior resistance to this exact organism-drug pair is far more likely to be resistant again — but it is nowhere near the ~100% a leaked label would produce.

**Verdict: legitimate patient history. Included**, with every window restricted to `t >= 1` day.

### 3.2 Laboratory results — cleared

`Period_Day` is constant at `14`, which documents that every lab aggregate summarises the **14 days before** the culture. The window closes at the culture, so no post-culture value can enter. **Verdict: included** (the constant column itself is dropped for zero variance).

### 3.3 Organism identity — cleared for the stated prediction moment

The organism is a culture result, so it would be leakage for a *pre-culture, empiric* task. Under the prediction moment defined in section 1 it is known by construction. To keep this honest rather than convenient, the feature selection experiments include an **organism-blind arm** that removes the organism entirely and reports how much performance depends on it (see `04_FEATURE_SELECTION/FEATURE_SELECTION_REPORT.md`).

### 3.4 Derived patient history — cleared by construction

> Per patient, ALL culture orders (positive and negative, 751,075 in total) are sorted by order_time and every counter is a cumulative sum SHIFTED to exclude the current order, so no feature can see its own outcome. Negative cultures are included in the denominator because a history of repeated negative cultures is clinically informative and excluding it would bias the prior-culture counts upward. Orders that share an identical timestamp are ordered by order id, and the current order is always excluded regardless.

## 4. Leakage across the train/test split

53.834% of patients (152,735 of 283,715) have more than one culture order, and one patient has 175. Random row-level splitting would therefore put the same patient — often the same organism, sometimes the same week — on both sides, so the test set would partly measure memorisation.

**Action taken.** All splits are **grouped by `anon_id`**, so a patient appears in exactly one of train / validation / test. A **temporal holdout** is additionally reported as a deployment-realistic check (see `docs/ML_PROBLEM_DEFINITION.md` §5).

## 5. Summary — every exclusion and why

| Variable | Decision | Reason |
|---|---|---|
| `anon_id` | Exclude from features | Patient identifier; memorisable. Retained only to group the split. |
| `pat_enc_csn_id_coded` | Exclude | Encounter identifier; no clinical content. |
| `order_proc_id_coded` | Exclude from features | Order identifier. Retained to link a prediction to its culture. |
| `was_positive` | Exclude | Culture result; constant (=1) after filtering to labelled rows — zero variance. |
| Resistance tokens inside `organism` | Exclude | The label restated in text. 21,879 rows affected; stripped by the normaliser. |
| `resistance.order_time_jittered_utc` | Exclude | Byte-identical duplicate of the cohort order time. |
| `prior_med` rows with `t == 0` | Exclude | 1,034,527 same-day rows cannot be separated from empiric therapy started after collection. |
| `medication_category` | Exclude | Redundant 1:1 surrogate key for `medication_name`, and misleading as a class (CEF/CEF1 = cefazolin, CEF2 = ceftriaxone). A real class is derived from the name instead. |
| `Period_Day` | Exclude | Constant (14) — zero variance. Documents the lab window. |
| `susceptibility`, `severity`, `y_3class` | Exclude from X | These are the target. |
| `order_time_jittered_utc` (raw) | Exclude | Raw timestamp; replaced by year/month/day-of-week/hour features so the model cannot key on an exact instant. |
| `organism` (raw) | Exclude | Replaced by the cleaned `organism_clean` / `organism_genus` / `organism_group` fields. |
| `age` (raw string) | Exclude | Replaced by `age_band_ordinal` and `age_midpoint_years`. |
| Prior resistance features | **Include** | Verified strictly >= 1 day before the index culture; predictive but far from deterministic. |
| Prior medication features | **Include** | Restricted to `t >= 1` day before the culture. |
| Lab aggregates (14-day window) | **Include** | Window closes at the culture. |
| Derived prior-culture history | **Include** | Cumulative sums shifted to exclude the current order. |
| `organism_clean` / genus / group | **Include** | Known at the stated prediction moment. An organism-blind ablation is reported. |
